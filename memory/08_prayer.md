## 앱 데이터 (build-data.mjs `buildPrayer`)
- stage 3, name `암미야 기도문`, 단원 29개 / 표현 368개. id `pray_<번호>` (예 `pray_7-1-1`), `unit: '표현'`, `group` = 장("7. 요청의 기도")
- 순서: 파일 이름 번호의 자연 정렬 (1, 2, 2-1, 2-2, 3, 4, 4-1 … 7-1, 7-1-1, 7-2 … 7-10, 8). 리스트 파일 순서(2-1 이 2 보다 먼저)는 따르지 않음
- 아랍어 정리: `(ع)` 제거, 떨어진 `! ? . , / ؟ ،` 는 앞 단어에 붙임. 괄호 안 다른 표현 `(أَوْ …)` 은 그대로 둠
- `(9번 표현이 없음)` → 그 표현 `noAudio: true` (text.js 에서 syl 0.05 → 시간 거의 0, Karaoke 에 "녹음에 없는 표현이에요", 번호 버튼 비활성)
- `(N파트로 나눌것)` 메모는 무시 — 표현 번호를 눌러 표현별 반복이 되므로 파일을 나눌 필요가 적음
- 기도문은 **제목 감지 끔** (`alignAuto(..., { intro: false })`): 8장 첫 표현 "아민"(짧음)을 제목으로 오인했었음

## 녹음 ↔ 글 일치 판정 (`timingQuality`) → 12개 단원 `autoTiming: false`
| 이유 | 단원 |
|---|---|
| 느림(<3음절/초) — 표현을 반복해 읽은 것으로 보임 | 4-3, 7-1-1, 7-4, 7-5-1, 7-6-1, 7-9-1, 7-10 |
| 빠름(>7음절/초) — 빠진 표현이 있어 보임 | 7-5, 7-9 |
| 말소리 묶음(0.9초 쉼 기준) < 표현 수 | 7-6, 7-8-1 |
| 표현 경계가 고르지 않음(1.5배 벗어난 표현 30% 초과) | 7-8 |
- 이 단원들은 `start` 없음 → 앱은 색칠 없이 재생·구간 반복만, 본문 위 안내 카드 + [타이밍 맞추기] 버튼
- 사용자가 타이밍을 맞추면(`bible:verseMarks:<id>`) 그때부터 색칠·표현별 반복 (검증: 7-9 에서 7번 눌러 저장 → 10초에 3번 표현 강조)
- 녹음을 귀로 확인한 게 아니라 길이·쉼 통계로 추정한 판정. 확인 후 모두에게 고정하려면 passages.json 에 start + startFixed
